# 設計書: 設定画面とチップの差分入力モード

- 作成: 2026-10-06
- 状態: 実装済み（2026-10-06。画面での確認は11章をオーナーが行う）

## 1. 目的

- チップを「20枚との差」で入力できるようにする。
  - 18枚なら `-2`、20枚なら `0`、23枚なら `3` と入力する。
- 設定を変える画面をホームから開けるようにする。
  - この画面は、今後の入力やルールの設定もまとめて置く場所にする。

## 2. 方針（結論）

### 保存する形は変えない

- Firestore の `chipRow` には、今までどおり「持ち枚数」を文字列で保存する。
- 差分モードで変えるのは、入力欄での**見せ方と読み取り方だけ**にする。
- 理由: チップは、保存された `chipRow` を読み込むたびに `recalcFinalStats` で計算し直している。
  - 半荘の `finalScores` は保存時に確定するが、チップはそうなっていない。
  - 保存する値の意味を変えると、過去のグループのチップ点まで変わってしまう。
- 保存する形を固定すると、次の利点がある。
  - 計算・集計・分析・共有画像を一切触らずに済む。
  - モードをいつ切り替えても、過去のデータは変わらない。

### モードはユーザー単位の設定にする

- 保存先は `users/{uid}` にする。
- 入力モードは「自分の打ち方の好み」で、結果を変えるルールではない。そのため、グループではなくユーザーにひもづける。
- スマホとPCで同じ設定になる。

### 既定は「持ち枚数」

- 既定は今の動きと同じ「持ち枚数」にする。
- 設定を変えるまで、今の挙動は何も変わらない。

```
入力欄（モードに応じた表示）
   │  chipInputToCount(入力, モード)   ※ここだけがモードを知る
   ▼
chipRow = 持ち枚数の文字列（保存形式は今と同じ）
   │
   ▼
recalcFinalStats / 結果表 / 分析 / 共有画像（変更なし）
```

## 3. 画面

### 3.1 ホーム（`src/Home.jsx`）

- 「集計・分析」カード（`Home.jsx:296-304`）の下に「設定」カードを足す。
  - 見た目は「集計・分析」カードと同じで、見出しとボタン1つ。
- ボタンを押すと `/settings` へ移動する。

### 3.2 設定画面 `/settings`（新規 `src/Settings.jsx`）

```
設定                                  [ホームに戻る]
──────────────────────────────
入力のしかた

チップ
  ○ 持ち枚数で入力      例: 18枚 → 18
  ● 20枚との差で入力    例: 18枚 → -2、20枚 → 0
```

- 選んだ時点で保存する（保存ボタンは置かない）。
  - 成功したら「保存しました」と出す。
  - 失敗したらエラーを出し、選択を元に戻す。
- 読み込み中はラジオボタンを押せないようにする。
- ルートは `App.js` の PrivateRoute 配下に、`Dashboard` とは別の要素として足す。
  - `Dashboard` 配下のパスに置くと、`renderContent` によってホームへ戻されてしまう（`Dashboard.jsx:766-768`）。
- `SEO` に `robots="noindex, follow"` を付ける（`Login` や `Signup` と同じ）。

**今後の拡張**

- backlog にある「ルールのプリセット」（順位点・チップ配点・返し点）も、この画面に「新しいグループの既定ルール」として足す想定。
- ただし、こちらは結果を変えるルールになる。そのため、ユーザー設定には**既定値だけ**を持たせ、グループを作るときに `groups/{id}.settings` へコピーする。
  - 今 `Home.jsx:119-123` で初期値を入れているのと同じ流れになる。
- 「入力のしかた」（ユーザー単位）と「ルール」（グループ単位）を混ぜないこと。

### 3.3 グループ画面のチップ行（`GameResultsTable.jsx`）

| | 持ち枚数モード | 差分モード |
|---|---|---|
| 行見出し | チップ | チップ（差） |
| 空欄のときのプレースホルダー | `20` | `0` |
| 保存値 `"18"` の表示 | `18` | `-2` |
| 空欄の意味 | 20枚（今と同じ） | 差0（＝20枚） |

- 行見出しにモードを出すので、今どちらのモードかがひと目で分かる。
- 「空欄は20枚扱い」は今まで画面のどこにも出ていなかったが、プレースホルダーで分かるようになる。
- PC用とモバイル用の2つの入力欄（`:214-219` と `:384-389`）を、同じ部品に置き換える（6章）。

## 4. データ

### 4.1 `users/{uid}`（新しく使い始める）

```
users/{uid}
  preferences:
    chipInputMode: 'count' | 'diff'   // 無いとき・不明な値のときは 'count'
  updatedAt: serverTimestamp()
```

- `setDoc` でドキュメント全体を上書きする。
  - CLAUDE.md の流儀（merge なし）に合わせる。今このドキュメントには他のフィールドがない。
  - 将来フィールドを足すときは、読み込んだ全体に重ねてから書く。
- Firestore のルール:
  - リポジトリの `firestore.rules` では、自分の uid のドキュメントは読み書きできる。そのため、ルールの変更は不要。
  - ただし、本番に適用中のルールが同じかは確認できていない。11章の受け入れ確認で、実際に保存できることを確かめる。

### 4.2 `groups/{id}.chipRow`（変更なし）

- 持ち枚数を文字列で保存する。
- 空欄 `''` やキーが無いときは20枚として扱う。

## 5. 変換ロジック

追加先は `src/utils/scoreCalculation.js` の、`toRawScore` の近くにする。

- 入力の変換関数がこのファイルに集まっているため。
- いつもの単体テストのコマンド（`scoreCalculation.test.js`）で一緒にテストが走るため。

```js
export const CHIP_BASE_COUNT = 20;
export const CHIP_INPUT_MODES = { COUNT: 'count', DIFF: 'diff' };

// 入力欄の文字列 → 保存する持ち枚数（文字列）
// '' は ''（＝20枚）。整数でない・入力途中のものは null（保存しない）
export const chipInputToCount = (input, mode) => { /* ... */ };

// 保存値 → 入力欄に出す文字列
export const chipCountToInput = (stored, mode) => { /* ... */ };
```

**入力 → 保存の例**

| モード | 入力 | 保存する値 |
|---|---|---|
| count | `18` | `"18"` |
| diff | `-2` | `"18"` |
| diff | `0` | `"20"` |
| diff | `3` | `"23"` |
| diff | `-22` | `"-2"`（マイナスの枚数は今までどおり許す） |
| 両方 | `''` | `''` |
| 両方 | `-` だけ／整数でない | `null`（保存しない） |

**保存値 → 表示の例**

- `"18"` は、diff なら `-2`、count なら `18`。
- `''` やキーが無いときは、どちらも `''`。
- 数値として読めない保存値は、そのまま表示する。

**定数への置き換え**

- `recalcFinalStats` の中の `20` は `CHIP_BASE_COUNT` に置き換える。同じファイルの中なので、動きは変わらない。
- `GameResultsTable.jsx` と `shareResult.js` にも `20` がハードコードされている。これを同じ定数に寄せるのは任意で、今回のモードには必要ない。やるなら別のコミットにする。

## 6. 入力部品 `ChipInput`（新規 `src/components/Dashboard/ChipInput.jsx`）

**props**

- `storedValue`
- `mode`
- `disabled`
- `onCommit(countString)`
- `className`

**入力中の状態**

- 入力中の文字は、部品自身の state（下書き）に持つ。
- フォーカスが外れたら、保存値から作った表示に戻す。
- こうすると、`-0` や `05` のような途中の入力が、保存のたびに書き換わらない。

**保存のタイミング**

- 入力のたびに `chipInputToCount` を通し、`null` でなければ `onCommit` を呼ぶ。`onCommit` は今の `handleChipChange` をそのまま使う。
- `type="number"` では、`-` だけを入力した段階で `value` が `''` になる。
  - このとき `e.target.validity.badInput` が true になるので、その場合は保存しない。
  - これで「入力途中なのに空欄（20枚）として保存される」ことを防ぐ。

**入力欄の種類**

- 今の `type="number"` のままにし、`step="1"` を足す。
- `inputMode="numeric"` は付けない。iPhone の数字パッドにはマイナスキーが無いため。
- `type="number"` なら、iPhone でもマイナスを含む記号つきのキーボードが出る想定。ただしこれは実機で確かめる（11章）。
- 打てなかった場合は、持ち点の入力と同じ「±」ボタン方式に切り替える。
  - モバイルの欄は幅 `w-12` なので、その場合はレイアウトの調整が必要になる。

**モードの読み込み中**

- `disabled` にして入力できないようにする。
- 読み込み前の既定（count）のまま `-2` と打ってしまい、それが「-2枚」として保存されるのを防ぐため。

## 7. モード設定の読み込み

新規に `src/hooks/useUserPreferences.js` を作る。

- `AuthContext` の `user` から `users/{uid}` を `getDoc` で読む。
- 返す値は `{ preferences, loading, error, savePreferences }`。
- 使う場所は `Settings` と `Dashboard`。
  - `Dashboard` から `GroupDetail`、`GameResultsTable` へと、`chipInputMode` を props で渡す。
  - 今は設定が1つだけなので、Context は作らない。
- 読み込みに失敗したときは `'count'` として扱う。行見出しが「チップ」になるので、モードが違うことに気づける。

## 9. チップの合計チェック

- 4人の「差」の合計が0でないときに、チップ行の下に小さく注意を出す。
  - 例: 「チップの差の合計が -2 です（0で合います）」

## 14. 既存の不具合: グループ画面の取り直しが止まらず、入力が巻き戻る

コードと Firebase SDK のソースを読んで調べた。実画面では確かめていない。

### 原因

- `GroupDetail` の `useEffect`（`Dashboard.jsx:425-457`）は、`getDoc` でグループを取り直して `setCurrentGroup(freshData)` する。
- 依存配列に `currentGroup` があり、`freshData` は毎回新しいオブジェクトになる。
  - そのため、取り直し → `setCurrentGroup` → 再実行 → 取り直し…が**止まらずに回り続ける**。
  - 1周は通信1往復ぶんで、毎秒 5〜20 回程度と見積もった（実測はしていない）。
- 経緯:
  - 最初の版（`d16c38b`）の依存配列は `[]` で、画面を開いたときに1回だけ動く設計だった。
  - `ed378d9` で `[currentGroup, ...]` に変わり、そこからループになった。ESLint の警告に合わせた変更とみられる。
- `getDoc` が返す値には、送信中の `setDoc` も反映される。そのため「サーバーの古い値に戻る」わけではない。
  - 巻き戻りが起きるのは次の場合。
    - 取得結果が確定してから画面に届くまでに数msの隙間がある。
    - この隙間にキー入力が入ると、1つ前の値で上書きされる。
  - ループで取り直しが常に走っているため、この隙間に当たることがあり、間欠的に起きる。
  - 戻った直後に次の文字を打つと、戻った値に続けて保存されてしまい、入力が消える。

### 影響範囲

| 入力 | 影響 |
|---|---|
| チップ | 巻き戻ることがある |
| 結果表での既存半荘の点数編集 | 巻き戻ることがある |
| プレイヤー名 | 巻き戻ることがある（日本語変換中に崩れるおそれもある） |
| 配点・順位点 | 入力欄は戻らない。ただし裏で持っている設定値が古い値に戻り、表示と計算が食い違うおそれがある |
| 新しい半荘の点数入力 | 影響なし（別の state で持っているため） |

- そのほか、画面を開いている間は通信・再描画・コンソールへのログ出力が続く。
- 2025-10 に「スマホで数値入力が遅い」としてデバウンスを入れ、すぐ戻した経緯がある（`9b871a6` → `42c3f6b`）。これも同じ原因だった可能性がある。

### 対策（採用案）

- この `useEffect` を削除する。
  - 画面を開いたときの取得（`Dashboard.jsx:638-661`）で、同じ値をすでに読み込んでいる。
  - `useEffect` にしかない処理は、プレイヤー欄が空のときの補い（`players || ['', '', '', '']`）だけ。これは初回取得の側へ移す。
- 失うもの: 別の端末やタブで変えた内容が、ループのおかげで自動で反映されていた。削除後は、再読み込みするまで反映されない。
  - 自動で同期したいなら、あとで `onSnapshot` を使って作り直す（今回はやらない）。
- 次の2案は採らない。
  - 依存配列を `currentGroup?.docId` にする案（ループは止まるが、初回取得と二重に読む）。
  - 保存を入力の確定時（blur）やデバウンスに遅らせる案。ループが残ったままだと、遅らせた分だけ古い値に戻されやすくなり、悪化する。

### 確かめ方（オーナー、修正前後）

- ログインしてグループ画面を開き、何も操作せずに DevTools のコンソールを見る。
- 「recalcFinalStats: 計算開始」などのログが流れ続ければ、ループしている。
- 修正後は、開いたときの数回で止まる。
