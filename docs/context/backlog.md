## 次の改修候補
当面の方針: **まず仲間内で使ってもらえる形にする**（2026-10-06 オーナー判断）。見知らぬ人への露出は後回し。

1. **共有URL**（ログインなしで成績を見られる）: 卓の全員が見られる。仲間内で使う入口になる。Firestoreのルール変更が必要（現状は作成者だけが読める）。共有ページは `noindex`
2. **結果のシェアの続き**: 画像は実装済み（changelog 参照）。年間レポート、1人の成績カード、テキスト版（コピー用）などは未実装
3. **入力の省力化**: 直前のメンバーやルールの引き継ぎ、ルールのプリセット（順位点・チップ配点・返し点）
4. **リーチ棒（供託）の扱い**: 場に残った棒があると合計が10万点に足りず、2本以上で保存ボタンが無効になる。合計チェックの緩和、または供託の入力と加算
5. **ツモで飛んだときの入力**: 「飛んでない人の払いは画面に反映済み」という前提が違った場合に、飛んでない人の分も入れられるようにする
6. **対戦成績・相性**（誰に強い・弱いか）: `Analysis.jsx` の拡張で足りる見込み。保存データの変更は不要
7. **グラフ**（順位分布、収支の推移）
8. **実画面の自動確認**: テスト用アカウントとブラウザ自動操作（Playwright）で確認できる可能性。Firebase / Google の接続先がネットワーク許可に必要。未検証

### 保留: 検索流入の続き
土台とトップの計算ツールは 2026-10-06 に実装済み（changelog 参照）。続きは、仲間内での利用が固まってから。
- 解説ページ（ウマ・オカ、五捨六入、飛び賞など）は **優先度を下げた**。一般的なルール解説は強い既存サイトが多く、新しいドメインでは勝ちにくい。Search Console に数週間ぶんのクエリが溜まってから、実際に出ている語を見て判断する
- 認証待ちの「Loading...」: `AuthProvider` が認証確定までアプリ全体を「Loading...」にする。Googlebot の描画では問題なかったが、体感速度の面では直す価値がある（`PrivateRoute` に loading を持たせる）
- キャッシュ設定: `netlify.toml` / `_headers` が全ファイルを no-cache にしている。ハッシュ付きのJS/CSSは長くキャッシュできる（Service Worker の古い画面問題との兼ね合いに注意）
- GA4 に `calculator_used` が届くかの確認（未確認）

## 既知の問題・技術的負債（未修正）
- **順位回数 `rankingCounts` の食い違い**: 追加時は `baseFinalScores`（飛び賞前）、削除時の再集計は `finalScores`（飛び賞後）で順位を決める。結果表のセル手編集では更新されない（詳細は architecture.md）
- **全体上書き保存**: `setDoc` に merge がなく、2台で同時に編集すると後勝ち
- **Firestoreルール**: `groups` の create が `userId` を検証していない（ログイン済みなら誰でも、他人のuidで作れる）
- **未使用ファイル**: `GroupDetail.jsx`、`hooks/useGameManager.js`、`hooks/useFirebase.js`、`config/firebaseConfig.js`、`App.test.js`（CRA初期のまま）
- **`package-lock.json` が `env-cmd` とずれている**ため `npm ci` が失敗する（Netlifyのビルドは通っている）
- **`package.json` の `build:dev` / `build:prod` / `deploy:*`** は `env-cmd` と `.env.*` が前提だが、現行の運用（Netlify自動デプロイ）とは無関係
- **プレイヤー名の表記ゆれ**: 名前の文字列だけで識別しているため、表記が違うと別人として集計される
- **ルールが固定**: 返し点は30000固定（グループ設定にない）。順位点は5種類の選択肢のみ
- **Service Worker の precache 一覧**（`/static/js/main.chunk.js` など）が、CRA 5 のビルド出力名と合っていない可能性（未検証）
